# 招聘业务数据清空

公开版本不附带真实业务数据、JD 原文或数据库备份；示例和验证仅使用明确合成或已获准公开的数据。

`reset-recruitment-data.sql` 是 MySQL 8 手工维护脚本，不属于部署迁移，不接入 Flyway。
默认只预览逐表总数、待删除数量、保留数量和删除条件；不会删除业务记录。
预览仍需创建临时表和临时使用的存储过程，需要 CREATE ROUTINE、ALTER ROUTINE、EXECUTE、CREATE TEMPORARY TABLES、SELECT 权限；执行另需 DELETE、UPDATE。

## 保留范围

- 组织、账号、成员关系、角色权限、部门支持关系、企业微信目录/同步状态/显式关联及身份审计。
- 客户、客户项目、客户岗位、负责人归属及客户对象授权。
- 工作日历及发布版本、来源渠道。
- 公司默认评分方案（ID 尾号 11）、其全部版本及引用的受控条件；默认条件版本（尾号 13）。
- 公司默认权重方案（尾号 21）及全部版本；个人方案删除。
- 面试通知模板、占用期限策略及历史、个人超时阈值、统计指标定义与版本。
- 邮件 IMAP 处理游标，避免清库后重新采集历史邮件。
- 数据库迁移记录、历史工作台阈值表（若存在）、登录会话。

其余清单内数据清空：JD、需求、候选人及全部简历、个人筛选、匹配评分、招聘流程、推荐、面试日程及外部日历投影、通知、Offer、入职、风险与核验、月报、统计事实、导出、邮件采集记录及与 JD 绑定的邮件路由、异步任务、Outbox、搜索同步记录、业务对象授权及招聘交接记录。
受控条件表同时保存岗位数据，因此只保留公司默认方案相关记录，不能整表保留。
身份审计保留历史快照，可能包含已清理业务的历史标识；这不是个人数据彻底擦除工具。

## 执行步骤

1. 明确目标服务器及数据库；只能用于已授权清空的开发或测试环境。不要凭默认配置推断目标。
2. 停止所有应用实例、Worker、定时任务、邮件导入和其他写入者。预览也建议停写，以便计数稳定。
3. 完整备份数据库，并在隔离环境验证可恢复。保留本次备份、预览及执行输出。
4. 用独立 MySQL 连接选择目标数据库，执行原脚本进行预览。过程创建/删除会隐式提交，禁止复用已有业务事务的连接。不要使用客户端的忽略错误继续执行选项。
5. 核对预览后，复制脚本到仓库外，将末尾默认 CALL 替换为：

```sql
CALL hr_reset_recruitment_data('已经核对的目标库名', TRUE, 'BACKUP_VERIFIED_AND_ALL_WRITERS_STOPPED');
```

6. 在同一目标库执行副本，必须看到 COMMITTED 及逐表结果。原脚本始终保留默认预览，避免下次误执行。
7. 再运行原脚本，待删除数量应全部为零；检查账号登录、客户资料、工作日历及新建 JD/导入简历流程。

脚本使用事务 DELETE，外键保持开启，自引用先在事务内解链；任意 SQL 异常回滚。
未知表、缺表、非 InnoDB 表、触发器、跨库入站外键及未识别授权/交接类型会阻止运行，应复核脚本，不能直接绕过检查。
后续表结构变化后须重新核对依赖并运行验证器。脚本可重复执行，但不能替代备份。
SQL 无法证明备份有效或其他实例已停写；确认字符串是操作者声明，必须先实际完成上述步骤。

## 数据库外的关联内容

MySQL 清空不会删除对象存储/本地简历与导出文件、Elasticsearch 索引、缓存或 Broker 消息。
停写期间先记录本项目文件与索引范围，避免删库后丢失对象路径；仅清理已授权且确认属于本项目的数据。
清理本项目搜索索引并重建、失效相关缓存、处置本项目待处理及死信消息后才恢复 Worker，避免旧任务重放。
不能清空共享 Bucket、共享 Redis 或共享消息队列。数据库外清理不由本脚本执行。

## 恢复与验证

失败时数据库事务回滚；提交后只能从已验证备份恢复。保持停写，数据库和外部文件应恢复到一致时间点，再重建搜索索引。
连接中断后重新预览确认实际状态，不能仅凭客户端断开判断成功或失败。

本地静态验证：`python scripts/database/verify-reset-script.py`。
验证器还会使用内存 SQLite 合成数据核对外键顺序、公司默认方案多版本、整表保留、回滚及重跑；不会读取真实业务数据。
静态检查不证明真实 MySQL 语法、事务、重跑或恢复行为；实际交付状态见任务说明。
