# ATS 业务交互模式

## 招聘工作台

- 首屏围绕“今天要处理什么”，展示待筛选、待复核风险、待面评、待记录甲方反馈、即将面试和失败任务；统计只作为辅助。
- 每个任务卡说明对象、原因、截止时间、系统已完成内容和下一步主操作。支持批量处理但不隐藏逐项风险。
- AI 价值用节省筛选量、覆盖率、人工复核率和错误反馈闭环表达，不用虚构“AI 准确率 99%”。

## 搜索与候选人列表

- 搜索词、JD/筛选模板、结构化条件、四通道阈值、排序和人才池组成可保存模板；有效条件以可移除 chips 展示。
- 结果行优先展示候选人、目标 Application/JD、匹配摘要、证据覆盖、突出项、风险、负责人和最近动作。
- 区分 `Candidate`、`ResumeVersion` 与 `Application`，避免把一个岗位结果显示成候选人全局结果。
- 疑似重复且无权查看时展示脱敏存在性卡与协作入口。不得通过前端缓存泄漏联系方式或原始简历。
- 使用服务端分页/游标和虚拟化证据驱动优化；禁止获取 9999 条或全量数据在浏览器筛选。

## 候选人详情

桌面优先采用可调整双栏：左侧原始简历/结构化事实，右侧为当前 Application 的业务面板。顶部固定候选人、需求、阶段、负责人、简历版本和敏感字段可见性。

右侧页签建议按任务组织：

1. 匹配：硬条件、加权适配度、突出项、风险、证据轨和可靠性。
2. 流程：阶段、面试、正式面评和时间线。
3. 外派：甲方推荐快照、反馈、冷却/禁推与带风险推进。
4. 沟通：邮件模板、发送记录和提醒。
5. 历史：简历版本、事实冲突、合并/拆分与审计。

- 点击证据定位原始文件；若只能定位抽取文本，要明确“未定位到页码”。
- 原始简历、联系方式、年龄/性别、薪酬和私密备注分别受字段权限控制；无权区域显示原因与申请路径。
- 人工决定与 AI 建议并列但视觉权重不同：人工决定是事实，AI 建议始终带“辅助判断”语义。

## 评分与风险

- 总排序分可以用于列表排序，但详情首屏必须拆出四通道。未知硬条件以灰/橙状态显示，不默认为 0 分或不通过。
- 每个维度展示原始分、权重、贡献、证据、置信度和缺失策略；权重调节提供即时预览但保存后生成新方案版本。
- 突出项单独置顶，说明触发规则与证据；不能通过把总分拉高来伪装。
- 风险按阻断/需确认/提示分级，说明系统能确认的事实和不能确认的部分。一般风险由 HR 填理由后推进，界面保留持续标记。

## 流程管道与长任务

- Kanban 适合岗位阶段概览，列宽固定、列内滚动、看板区域横向滚动；同时提供可访问的列表视图。
- 拖拽前检查权限和目标状态，移动中防重复，失败恢复原列并说明后果；触发邮件/推荐等副作用前二次明确，不因普通拖拽静默执行高风险动作。
- 任务抽屉跨路由存在，展示批次进度、成功/失败/待复核数、队龄、暂停/取消/重试和失败项下载。刷新后从服务端恢复。
- 部分成功必须逐项可追踪；重试只重跑失败或明确选中的项目，不重新处理已成功项。
