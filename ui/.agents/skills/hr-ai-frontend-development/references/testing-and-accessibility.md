# 前端测试、响应式与可访问性

## 状态矩阵

仅检查本次改动可能影响的状态和调用路径：

| 变化 | 必要行为证据 |
|---|---|
| 文案、默认值、局部条件 | 实际文案/默认请求、切换或重置；涉及用户输入时保留校验 |
| 布局、标签、焦点 | 受影响组件的浏览器显示、键盘焦点、长内容及窄屏；复用已有交互测试 |
| API、权限、缓存、异步任务 | 对应成功、失败、重试、无权限/脱敏、并发或任务恢复；不能用布局截图替代 |
| 新页面或整体流程改造 | 实际支持的首次加载、数据/空态、部分数据、慢请求、失败、会话与权限、并发及长任务状态 |

只读审查和纯说明文件变更检查内容、链接和格式，不运行应用构建。修改可执行辅助脚本时增加语法和聚焦行为验证。不要为未受影响的页面状态逐项建立测试；必要的新行为和缺陷回归仍须有直接证据。

## 响应式与密集数据

- 优先服务桌面浏览器，同时保证窄屏基本可用。局部布局选择一个实际桌面宽度和一个受影响窄屏；新页面、全局布局或断点变化检查 390、768、1280、1440、1920px 中相关断点。文字缩放或可访问性变化增加 200% 缩放，不对无布局变化强制重跑全部视口。
- 使用 Grid/Flex、`minmax(0, 1fr)`、`min-width: 0` 和内容驱动断点。按钮组可换行，长中文、邮箱、文件名和 ID 不得撑破布局。
- 表格在自身区域横向滚动，固定候选人/主操作等上下文列；窄屏可切换摘要卡 + 详情抽屉，但不得静默隐藏风险或权限状态。
- 看板、简历查看器和双栏详情各自管理滚动，不制造嵌套滚动陷阱；可见滚动条用于提示可滚动区域。

## 可访问性

- 使用语义 HTML 与 Ant Design 可访问行为；所有图标按钮有可读名称，状态不只靠颜色，触控目标尽量不小于 44px。
- 对话框打开后聚焦标题/首个控件，Tab 被约束，Escape 遵循安全语义，关闭后返回触发点。
- 拖拽提供键盘/菜单替代路径；排序或阶段变化通过 live region 或明确 Toast 反馈。
- 焦点轮廓始终可见；骨架屏保持布局稳定；动画服从 `prefers-reduced-motion`，不使用延迟工作的装饰动画。
- 简历 PDF 不可访问时提供结构化文本视图；屏幕阅读器可以理解评分标签、证据来源和风险等级。

## 自动化测试

- Vitest：纯评分展示、权限能力、格式化、query key、轮询调度、任务状态合并和 Zod schema。
- React Testing Library + MSW：以用户操作验证加载/错误/权限/脱敏/重复提交/部分成功，不断言组件私有结构。
- 架构契约测试：禁止页面直拼 API、硬编码 Token、长期 Token 存储、巨型全局 store、全量候选人请求，以及权限敏感字段绕过业务组件。
- Playwright：登录、JD/权重、上传与批量异常、筛选与证据、风险确认、面试/面评、甲方推荐和跨角色越权；覆盖刷新恢复和失败重试。
- 视觉回归只覆盖稳定关键骨架和状态，不用大批脆弱全页快照替代行为测试。

## 交付门槛

生产前端代码变更运行受影响测试、lint 和生产构建；当前 `npm run build` 已含 `tsc -b`，其成功结果满足类型检查，不再为同一源码重复运行 typecheck。独立类型检查仍可用于调试。浏览器验证本次涉及的交互、显示或权限路径；已完成且相关源码/配置未变的同任务证据可复用。只报告本次相关但未验证的边界，不列无关的缺失环境清单；未验证真实后端时不声称联调成功。
